System flow

How the credential lifecycle works

The product experience is intentionally split into a professional issuance flow and a focused verification flow, similar to how public-sector document systems separate administrative actions from citizen access.

1. Institution approves issuer The trusted registry ensures only authorized organizations can create credentials.
→
2. Credential is created and signed Payload data is normalized, hashed, and signed before a proof record is anchored.
→
3. QR and PDF are generated The holder receives a shareable certificate with a direct link into the verifier portal.
→
4. Verifier checks live trust Status, issuer approval, signature validity, and hash integrity determine authenticity.
